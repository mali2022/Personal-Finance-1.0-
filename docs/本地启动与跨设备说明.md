# 本地启动与跨设备说明

更新时间：2026-11-18（Asia/Shanghai）

本说明适用于从 C 盘复制到 `G:\Personal Finance` 的本地项目。C 盘原目录继续保留，G 盘为可移植副本；两个目录不要同时启动同一组端口/数据库写入，避免重复实例。

## 双击入口

| 文件 | 用途 |
| --- | --- |
| `打开PersonalFinance.bat` | **本地完整模式（静态）**：启动本机后端（5085），由后端直接托管已构建前端（`backend/src/PersonalFinance.Api/wwwroot`），然后打开浏览器。**不需要 Node/Vite**。 |
| `启动PersonalFinance.bat` / `快速进入.bat` | 与 `打开PersonalFinance.bat` 相同，保留旧入口名称。 |
| `打开演示界面.bat` | **演示模式（可选）**：只启动前端（5173，MSW 演示数据），不需要后端/数据库/.NET；需要 Node 与完整的 `frontend/node_modules`。G 盘副本若未安装前端依赖，请先在 `frontend` 执行 `pnpm install`。 |
| `启动云端账本.bat` | 打开线上云端账本（`https://personalfinance.invalid`），需要网络。 |
| `停止PersonalFinance.bat` | 停止由本地启动器创建的进程；不会关闭 SQL Server、浏览器或非本启动器创建的进程。 |
| `备份并升级本地数据库.bat` | 先备份、校验 `PersonalFinanceWeb`，再应用当前程序的 EF 迁移；需输入大写 `YES` 确认。 |

## 运行条件

| 组件 | 要求 |
| --- | --- |
| Windows | Windows 10/11，Windows PowerShell 5.1 或更高 |
| .NET | .NET 10 SDK/运行时（本地完整模式必需） |
| SQL Server | 默认实例 `MSSQLSERVER`，数据库 `PersonalFinanceWeb`；本地启动器不会自动建库或迁移 |
| Node.js | 仅 `打开演示界面.bat` / Vite 开发模式需要（Node 20+）；静态完整模式不需要 |
| 前端产物 | 静态完整模式使用 `backend/src/PersonalFinance.Api/wwwroot`（已由 `frontend/dist` 复制）；修改前端后需重新构建并复制 |

启动器会按以下顺序自动查找运行时，不再依赖 C 盘写死的路径：

1. `PF_NODE` / `PF_DOTNET` 环境变量；
2. `scripts/local-runtime.json` 中显式配置（可选，路径不存在时自动继续查找）；
3. 系统 `PATH`；
4. `.tools\node` / `.tools\dotnet`（如自行放入便携运行时）；
5. 常见安装目录与 Codex/DSH 自带运行时目录。

如果需要固定某台设备的路径，可编辑 `scripts/local-runtime.json`；不要把该文件写成另一台设备不存在的路径。

## 首次在 G 盘启动

1. 确认 G 盘副本完整（本说明文件位于 G 盘项目根目录）。
2. SQL Server 默认实例已启动，且存在 `PersonalFinanceWeb`。
3. 双击 `打开PersonalFinance.bat`。若提示 `SCHEMA_OUTDATED`（本地数据库结构落后于程序），启动器会拒绝启动并提示升级：
   - 先关闭正在运行的本地服务；
   - 双击 `备份并升级本地数据库.bat`，阅读提示并输入 `YES`；
   - 等待备份校验和迁移完成，再重新双击 `打开PersonalFinance.bat`。
4. 如果只想查看界面、不接触本地数据库，双击 `打开演示界面.bat`（演示数据，不会写入正式账本）。

本地日志在 `.local-run\logs\`；进程记录在 `.local-run\processes.json`。若从 C 盘复制了整个目录，请勿把旧 `.local-run` 一起带过来（当前复制已排除该目录），否则进程归属校验会拒绝操作。

## 静态本地模式（默认）

为避免每台设备安装 Node 依赖，`打开PersonalFinance.bat` 默认使用 `-Static`：

- 后端在 5085 端口同时提供 `/api/*` 与前端静态文件（`UseStaticFiles` + SPA fallback）；
- 启动器只启动 `.NET` 后端，不再启动 5174 Vite，也不需要 `frontend/node_modules`；
- 页面地址为 `http://127.0.0.1:5085/`；
- 端口 5085 自 1.0.0 正式版（发布号 2026.11.18.1）起使用，2026-11-18 及以前为 5080；桌面版「个人记账」默认占用 5080，两者可同时打开。
- 前端有改动时，重新构建并复制：

```powershell
cd frontend
node node_modules/vite/bin/vite.js --configLoader runner build
robocopy dist ..\backend\src\PersonalFinance.Api\wwwroot /E
```

G 盘副本已包含 `backend/src/PersonalFinance.Api/wwwroot`。若前端产物缺失，启动器会提示先复制 `frontend/dist`。

## 跨设备使用

项目路径全部基于 BAT 所在目录（`%~dp0`）和脚本目录（`$PSScriptRoot`），因此可以整体复制到其他盘符或电脑。跨设备前请确认：

- 目标电脑具备上表运行时；
- `frontend/node_modules` 已随项目复制（或在该电脑执行 `pnpm install`）；
- 目标电脑有可用的 SQL Server 默认实例与 `PersonalFinanceWeb` 数据库。数据库不在项目文件夹内，需要另行备份/还原（例如使用 `备份并升级本地数据库.bat` 或既有备份流程）；
- 首次运行若数据库结构落后，先执行数据库升级流程；
- 不要复制 `.local-run`（运行状态）、`backend\.backups`（备份）或任何密钥/凭据到不可信设备。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示找不到 node/dotnet | 安装对应运行时，或设置 `PF_NODE` / `PF_DOTNET` 指向可执行文件 |
| 提示端口被占用 | 关闭占用 5085/5174 的程序；启动器不会强制结束其他程序 |
| 提示 `SCHEMA_OUTDATED` | 先备份，再运行 `备份并升级本地数据库.bat` |
| 数据库连接失败 | 确认 SQL Server 默认实例运行且 `PersonalFinanceWeb` 存在；启动器不会自动建库 |
| 演示模式打不开 | 确认 Node 可用、`frontend/node_modules/vite/bin/vite.js` 存在，且 5173 未被占用 |
| 停止失败 | 查看 `.local-run\logs` 与 `.local-run\processes.json`；启动器只停止自己创建的进程 |

## 安全说明

- 启动器不读取/打印数据库密码、JWT 密钥或登录凭据；数据库配置沿用项目既有 `appsettings` 与环境变量。
- `备份并升级本地数据库.bat` 会先执行 `BACKUP ... WITH CHECKSUM` 与 `RESTORE VERIFYONLY`，失败即停止；迁移不可自动回滚，请保留备份。
- 本轮只做项目文件迁移与启动器本地化，**未上传云端、未部署生产、未修改生产数据库**。
