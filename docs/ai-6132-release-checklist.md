# Personal Finance 6.13.2 发布检查清单与健康检查方案

候选版本：2026.10.28.3。本文为发布准备，不表示生产部署已执行。

## 发布前门禁

- [ ] 核对最终验收报告中的未通过、未执行、环境限制项，不能仅凭一次重跑覆盖此前失败。
- [ ] 所有关键集成测试实际执行，无跳过替代通过；真实 AI 只传输隔离合成数据。
- [ ] 对历史原始附件、解析文档、投资 IRR/XIRR 的覆盖范围做明确产品说明；未支持项目不可宣传为全部支持。
- [ ] 确认前后端公告一致、产品版本 6.13.2 / 发布编号 2026.10.28.3，尚未发布的候选内容可继续修正；已发布后不同代码必须新建版本。
- [ ] 使用 release-build-receipt.json 验证源码与构建产物冻结；任何源码或产物变化均重新构建、验证和封存。
- [ ] 保存当前后端镜像 ID、静态文件、nginx 配置和加密密钥卷的恢复方案；不得把密钥打包进发布产物。
- [ ] 按现有 backup.sh 流程生成新的生产库备份并校验，备份应包含数据库中的附件；先确认旧备份保留策略。不可用隔离合成库备份代替生产备份。
- [ ] 确认备份成功后，进入维护窗口暂停后台 AI/workflow/写请求，使用迁移账户执行已校验升级；应用运行账户不临时提升为数据库管理员。
- [ ] 复核 Production 环境、签名密钥、连接串、DataProtection 卷、AI 服务启用、受保护服务商密钥、实际模型容量及服务商账户状态。

## 迁移与应用发布

1. 先确认备份可读、VERIFYONLY 和恢复演练证据。升级只新增 FullFinancialAccess（默认 false），不得替旧用户开启全量授权。
2. 应用 AiUnifiedFinancialConsent；校验旧用户授权版本及原授权字段保留，新列默认 false。
3. 发布已封存的 linux-x64 后端和同版前端，沿用现有备份与切换流程。
4. 先检查 READY/buildId，再开放入口及后台任务。AI 不要求配置价格或预算；仍保留上下文、并发、超时及循环保护。

## 发布后健康检查

- [ ] /api/health 返回 READY，buildId 与封存 API DLL SHA256 一致；数据库与 worker 就绪。
- [ ] /release-info.json 返回 2026.10.28.3，响应不缓存；/settings/updates 与 /updates 正常显示公告。
- [ ] 未登录访问财务 API 被拒绝；两个专用合成账户互相不能读取对方流水、账户、任务、依据或附件。
- [ ] 专用合成用户明确开启全量授权后，查询长周期汇总、连续多工具与分页；缺少价格正常执行，来源、期间、币种及缺口可见。
- [ ] 撤销授权后新模型/新工具读取被拒绝，旧上下文缓存失效；不能仅检查 UI 开关状态。
- [ ] 记账生成草稿不自动过账；修改、删除、余额及高风险操作仍需独立权限和确认。
- [ ] 智能对账、EntryWorkflow 的正常与保存冲突流程通过；不修改正式用户账务作验证。
- [ ] 日志能区分服务商 401/402/429、容量与网络错误和本地运行时超时；不能重新出现内部费用/Token/调用次数预算错误。
- [ ] 观察数据库锁、并发 DbContext 异常、工具重复、排队、失败率、请求持续时间及磁盘容量。出现跨用户数据、撤销失效或写权限绕过即停止 AI 入口并回滚。

## 回滚

- 首选切回原后端镜像和静态文件，保留向后兼容的新数据库列；不要在持续有写入时覆盖整库。
- 如必须降级 schema：维护窗口中停用相关任务，确认备份点，执行已演练的 Down；FullFinancialAccess 被删除，再升级会恢复为 false，需要用户重新明确授权。旧字段和财务数据应保留。
- 如必须恢复整库：明确备份时间之后的数据恢复方案与业务写入冻结；只能恢复至已核对的目标数据库，不能把测试恢复库误当生产。
- 回滚后重新执行 READY/buildId、身份隔离、账目与附件完整性、登录会话及基础记账检查。
