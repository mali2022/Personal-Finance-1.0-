## 数据模型与迁移判断

复用既有 EF Core `StoredDocument`，不新增表，因此本阶段不需要数据库结构迁移。

| Kind | 内容 |
|---|---|
| SpendingOptimization | 完整 ValueProblem、ValueSolution、算法版本、计算时间、来源决策根 ID |
| SpendingPreference | 主动授权、维度、手动权重，文档版本保护 |
| SpendingFeedback | 方案来源、两类真实支出 ID、实际次数/时间/满意度、主观维度反馈、目标说明、再次选择、学习授权与明确重要性权重 |

候选可携带本人 AI 运行来源 ID；保存优化快照时验证来源所有权。模型调用不在数据库写事务中执行，求解也在保存事务之前完成。模拟方案、偏好和复盘不写入正式交易、分录或预算，不改变现有账务统计。

## 求解与财务规则

1. 固定商品：整数数量，金额必须等于确认单价×数量，不能拆价购买。数量上限 20。
2. 分档与可分配金额：最多 8 个明确金额/效用档位，包含不购买状态；不进行隐含线性插值，不假定金额翻倍即价值翻倍。
3. 单项金额、未来费用、时间、精力和效用均由用户输入确认；未确认档位不能作为可行购买结果。
4. 购买总额与未来费用分别输出。组合优惠显式叠加，以购买金额为上限；总拥有成本=购买金额−优惠+未来费用；剩余资金=预算−总拥有成本。
5. 安全检查保守地假设全部费用在期初支付，不计未来收入。预算余额、可用现金安全底线、最大总成本、小时、精力、必选/排除/依赖/互斥及最低主观目标全部先检查。
6. 某维度的组合效用采用饱和合并：`S = 10 - (10 - 基准分) × Π(1 - 档位分/10)`。这是公开的主观聚合假设，不代表因果效用或财务收益。
7. 偏好分仅为同为 0–10 分的主观维度加权平均。金额、小时、精力不与其直接相加。帕累托支配同时考虑成本、时间、精力和每个价值维度。
8. 输出自定义、均衡、储蓄及各维度优先的不同选择，按配置去重。可行组合不足三个时如实说明。不消费基准始终保留；若违反必选目标，会明确标为不可行参考。
9. 财务机会成本仅为用户明确利率下的简单利息假设：`总成本×年率×天数/365`。未提供年率时未知；不预测保留现金的真实投资收益。

### 算法边界

候选最多 100 项、维度最多 12、优惠最多 30。小问题在 `min(131072, max(512, floor(262144/候选数)))` 个完整组合以内进行枚举；更大问题采用宽度 192 的多目标确定性束搜索。总展开限制 500000；求解检查 5 秒期限和取消令牌；全局最多同时求解两项，超载返回明确错误。

近似搜索不能保证全局最优或一定找到所有可行组合。即使完整枚举，也只返回有限的代表性方案；“非劣解”明确指返回集内的非劣解，不宣称完整全局前沿。相同问题、算法版本和资源策略的成功求解可复现；超时返回错误，不把被中断结果包装成最优解。

## 多目标与不确定性

支持权重重排、成本/保留资金图、价值雷达、支配关系、并列与取舍。调整权重只读取一份已保存快照并重算主观分，不重查完整账本，也不改写历史金额或快照。

情景支持预算、最低保留、价格、后续费用、时间、预计次数、寿命和单维度权重。界面默认倍率 0.8/1/1.2，可修改；API 最多接收 9 个倍率。分析重新评估同一批返回候选，展示排序变化、所有情景仍可行的方案、预算/现金/小时/精力必要阈值，以及其他权重固定时两方案等分的临界权重。情景范围不是发生概率，单项阈值不替代其余硬约束。

## AI 与偏好边界

AI 设计器只接受短文本需求及另行授权的本人财务快照。明确条件必须是用户原文片段，推测、目标和待补信息分开。预算提示从用户原文提取，仍需用户点击确认；模型不得给定售价、满意度或最优解。导入的想法保持未确认，用户补齐价格、效用和期限后才调用正式求解器。

没有自动外部询价或未经核验的价格填充；用户提供的外部价格可记录来源和确认时间。AI 解释只使用已保存计算结果，财务卡片仍由计算服务提供；模型输出出现未经验证数字或不允许的收益承诺会被拒绝。两个 AI 接口均不向模型提供可执行工具，核对调用前后隐私授权版本。

偏好默认关闭。只学习用户授权且明确填写的重要性权重，不凭支出推断喜好。至少三个独立决策来源后，建议权重=80%归一化手动权重+20%明确反馈归一化均值。重新评估同一来源不会充当多次独立证据。建议必须由用户主动应用。暂停拒绝新学习贡献；撤销只移除指定反馈的学习影响，保留复盘；重置清除所有学习影响并暂停，仍保留真实复盘。当前最多保留 200 条复盘，达到上限需更新已有记录。

## API（均在 /api/spending-value 下）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /optimize | 求解并保存不可变快照 |
| GET | /runs、/runs/{id} | 分页历史与完整结果 |
| POST | /runs/{id}/reevaluate | 新条件重新计算，保留来源根，不覆盖历史 |
| POST | /runs/{id}/weights | 已存候选主观权重重排 |
| POST | /uncertainty | 参数情景、排名变化、必要阈值和等分权重 |
| POST | /designer、/explain | 待确认 AI 想法、已计算方案的定性解释 |
| GET/PUT | /preferences | 查询依据与版本保护更新手动权重/授权 |
| POST | /preferences/reset | 清除学习影响并暂停 |
| POST/PUT | /feedback、/feedback/{id} | 新建/更新消费反馈 |
| GET | /feedback/{id} | 从真实支出读取成本、追加费用、使用成本、预测和主观偏差 |
| POST | /feedback/{id}/revoke | 版本保护撤销该条学习影响 |

持久化写入沿用幂等键、用户写锁、审计和文档版本。错误沿用项目的 `message/code/traceId` 结构。反馈只能关联本人同币种已确认支出，购买与追加费用不可重复计数。交易失效或没有实际交易时不假设实际成本为零；没有满意度反馈时不推断满意/不满意。组合项目不混用互不相关的使用次数分母。
