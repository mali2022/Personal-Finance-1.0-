# 投资收益率2.0：缓存与迁移

开发候选，未发布。2026-11-02。

## 为什么扩展数据库

原模型无覆盖交易、估值、汇率更正的统一持久版本。资产自身 Version 无法覆盖历史汇率及关联账务变化，单实例内存通知无法保证多实例失效。

迁移 `20261102110000_InvestmentReturnRevision` 为 finance.Users 增加基础设施专用 uniqueidentifier 列。该列有意不映射到 AppUser，也不加入 EF 模型快照或用户 API，避免被用户资料保存覆盖。后续迁移须保留此基础设施列。

FinanceDb 的同步/异步 SaveChanges 检测 InvestmentAsset、InvestmentTrade、InvestmentValuation、FxValuationRate、Account、FinanceTransaction、Entry、AssetAggregationPolicy及InvestmentBoundaryValue文档的新增、修改和删除，更新受影响旧/新 UserId 的随机版本。版本与数据在同一事务提交，回滚不改变有效版本。新用户尚未插入时更新零行，初始空版本下不存在该用户旧结果。

## 缓存边界

覆盖单资产及账户/组合，趋势/对比/报表复用单项计算缓存。每次先校验当前对象归属，再于一致性读取事务内读取持久版本。键包含数据库服务器及库名、用户、对象集合、起止日、报告币种、版本、Actual365/ExactDate政策版本。当前投资模型仅有 UserId，未扩展到财务空间共享；不得用于绕过空间授权。

每进程专用16MB容量，单项超过1MB不缓存，两分钟绝对过期。缓存保存序列化金额和结果，不保存服务或 DbContext。命中省去投资历史、估值、汇率读取与求根，仍执行认证、归属及版本查询。不同实例通过同一数据库版本拒绝旧键，旧内存项待过期或容量淘汰。

`calculationId` 用于核对结果是否复用，不是业务流水或权限凭证。暂未提供命中率及SQL读取量监控，不构成性能预算通过证据。

## 写入限制

版本覆盖 EF 跟踪保存。直接 SQL、ExecuteUpdate/ExecuteDelete、外部工具和数据库恢复不会自动更新版本。当前 Investment/Asset 服务未发现这类业务写路径。将来新增此类写入，必须在同一事务更新受影响用户版本；数据库恢复或外部修正后须停止服务、清空进程缓存再恢复请求。不能将此实现宣称为任意外部数据库修改自动失效。

## 部署及回滚

2026-11-02用户明确授权直至线上部署，现已完成：实际还原验证新备份后，生产应用20261102110000_InvestmentReturnRevision新增GUID列，再部署2026.11.02.4 /6.23.0。生产迁移记录及列存在检查通过；未修改投资业务数据。详细发布、备份及回滚证据见功能与验收报告第15节。

回滚时先停止新版本实例，恢复不依赖该列的应用；确认无需新缓存后可通过既有迁移流程回退此迁移，删除的仅为缓存版本列。保留原财务表及交易。禁止在新代码运行时先删除列；重启实例清除全部内存结果。

## 验证与未完成项

真实隔离SQL/HTTP用例通过：缓存复用、估值更正、汇率更正、撤销恢复、事务回滚、认证/用户隔离及并发读取。账户/组合缓存、最多20项批量收益及百万普通账本背景投资性能验证已补齐；明确项目归属更正也使用户版本失效。未实际部署两个进程，不将共享版本机制当作多实例实测；持久结果快照、共享财务空间投资及生产命中率监控未实现，完整账户边界快照不等于持久计算结果。
