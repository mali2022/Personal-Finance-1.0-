# 百万级账本测试与全局优化（2026-10-26）

## 范围与方法

在随机命名的独立 LocalDB 数据库中生成 1,000,000 笔交易、2,000,000 条分录：80 万支出、10 万收入、10 万转账，覆盖 2018–2025 年、CNY/USD/HKD、60 个账户、264 个分类和 200 个资料项。所有数据与用户均为合成数据，没有使用正式账务。

“百万级”指账本存量，不代表发送百万次请求，也不代表每个专用业务模块都有百万条实体。测试机器为 Windows、16GB 内存、Core Ultra 5 225，Release API 和 SQL Server LocalDB。结果包含 JIT、缓存及本机资源竞争影响，不能当作生产吞吐保证。

验证包含：100 个模块与明细 HTTP 探测；列表、深分页、排序、账户筛选和关键词搜索的 1/4/8 并发；多账户付款、退款、类型编辑、借入借出及删除恢复的写入核账；持续混合读写；360/1440 宽度真实 API 浏览器流程；独立 SQL 功能回归；数据库与分录完整性检查。专用模块的非空数据业务规则由功能回归覆盖，空数据 HTTP 探测只能证明端点与查询可执行。

详细原始结果位于本地 `verification/million-20261026`；该目录不随公开站点发布，私有会话凭据仅保存在被忽略的本地运行目录。

## 修复与优化

- 交易后余额按上海自然日汇总，再按精确时间、创建时间与 ID 还原日内顺序，减少百万分录排序。25 组账户/交易与原始精确聚合一致。
- 增加交易排序、分录覆盖、交易投影与退款原交易索引；账户过滤明确用户条件，减少扫描与回表。
- 首页、账户统计与高级报表合并重复聚合；分类统计只计算实际优惠分摊，按祖先分发统计行；异常规则在 SQL 中合并检测；历史回顾仅查询实际记账年份。
- 退款选项改为分页批量投影，省去重复详情与余额计算；无搜索结果立即返回，避免继续进行排序扫描。
- 大范围元数据命中搜索切换查询策略，保留金额、文本、项目、标签、分类及用户范围规则。
- 混合读写暴露出锁等待，新增已认证 GET 的 SNAPSHOT 一致性读取；保留写入幂等、并发版本和用户写锁。测试证明未提交修改不会被读取，提交后的修改可见。
- 取消全局 30 秒重复轮询，保留显式业务轮询与保存后更新。静置 62 秒的额外请求从 10 次降为 0。
- AI 工具元数据去除冗余默认值，恢复默认上下文预算；初始化迁移采用独立的 600 秒超时，不放宽交互请求的 15 秒测试期限。

## 性能证据与边界

初始 100 次探测有 16 次超时，另有 9 次为测试参数或前置条件错误；修正夹具后单独记录，未作为产品缺陷。优化版本的 100 次逐模块探测全部成功。原并发测试仍发现广泛关键词超时，调整查询后，1/4/8 并发的 78 次搜索全部成功。

代表性单请求结果：深分页约 1.81 秒、账户筛选约 1.10 秒、账户列表约 1.83 秒、高级报表约 3.4 秒、退款候选约 1.7–2 秒。各阶段运行条件与代码版本不同，这些为观测值，不作为严格同条件加速比。

广泛命中关键词在 8 并发时 P95 为 14.35 秒、最大 14.42 秒，接近 15 秒期限；异常汇总等完整账本统计仍可达到约 11–13 秒。它们可执行，但尚未达到交互秒开。后续需要按实际规模评估持久汇总、搜索索引及服务器资源，不应据本轮通过承诺任意并发容量。

百万账本写入验证的 7 组检查通过：12 个相同幂等请求仅落一笔、不同载荷返回 409；多账户付款精确核账；部分退款额度及关联保护；切换类型重建分录与旧版本冲突；借出借入连同还款撤销；删除恢复后的最终余额；超限导出明确拒绝。

## 当前无法满足或未证明的能力

| 能力 | 结论 |
| --- | --- |
| 单次百万条全量导出 | 不支持；实测返回 422，单次上限 100,000 条，需缩小筛选范围或后续增加异步分片导出。 |
| 自定义报表、部分管理分析的无限明细计算 | 不支持；现有实现有 100,000 条明细保护，需要缩小范围或改为数据库聚合。 |
| 投资 IRR/XIRR | 现有收益报表明确未输出；没有用现金流或盈亏冒充收益率。 |
| AI 与实时汇率提供商的生产容量 | 本轮未进行真实外部服务压测；内部解析、预算和功能测试不能证明提供商可用性。 |
| 所有专用模块均达到百万实体 | 未验证；百万数据集中在账本，专用业务通过独立合成夹具验证。 |
| 任意并发下的秒级响应 | 未达到；广泛搜索与全账本分析仍有上述长尾。 |

## 最终候选版本复测

持续混合读写 304.9 秒：887 次请求、99 组完整的新增/查看/删除/恢复循环，零失败，期末余额精确为 999.01 元，与逐笔计算一致。新增记账 P95 506ms、删除 P95 233ms、恢复 P95 261ms；退款无结果搜索 P95 7.99 秒。原始记录：`soak-final/{complete,results,summary}.json`。

最终矩阵 `optimized-release-validated` 共 334 次：323 次成功、11 次超过 15 秒期限。100 次逐模块探测及 1/4 并发全部成功；8 并发的 144 次有 11 次超时（金额排序 4、带年份范围的广泛搜索 5、账户筛选 2）。这是同时执行多类重查询的容量边界，不能用此前仅搜索的 78 次通过结果替代。没有提高期限、隐藏失败或据此承诺 8 并发可用。

持续写入新增了 207 笔使用合成分类的记录，导致一次旧测试断言错误地要求关键词仍严格等于初始百万笔。修正后的矩阵将该项限定到原始 2018–2025 年份，保留精确数量校验；中断的 `optimized-release` 原始记录保留，未计为产品故障。

最终功能回归：后端 491/491、前端 463/463，均零失败；发布完整性工具 5/5。真实 API 浏览器流程在 360px、1440px 均通过，覆盖登录、百万列表、详情退款入口与账户交易加载，无页面异常或 500。数据库 `DBCC CHECKDB`、约束、用户归属、分录平衡、退款额度、业务本金与还款余额校验全部通过，日志标记 `PF_INTEGRITY_PASSED`。

版本公告只描述实际优化，不声称所有百万级场景秒开或任意并发通过。
