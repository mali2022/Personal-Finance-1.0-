# Personal Finance 项目全部功能报告

检查日期：2026-10-25（Asia/Shanghai）  
检查对象：当前工作区前端、后端、路由注册、业务实现与测试代码。  
版本记录：`frontend/package.json` 为 **6.9.8**；发布目录 `currentVersion` 为 **2026.10.24.4**。两者分别是产品版本和发布版本。

## 1. 报告范围与结论

项目已经形成覆盖个人记账、账户资产、预算规划、薪酬社保、共同账本、专项财务、分析报告和 AI 辅助的综合财务应用。前端不是单纯演示页面，后端存在对应的接口、服务与数据实体；另保留显式开启的 Mock 模式用于开发和测试。

本报告的“已实现”表示在当前源码中找到页面/入口和对应服务，并不等同于所有功能均经真实数据库端到端验收。工作区存在大量已修改及未跟踪文件，本报告包含这些代码；未核对生产服务器，因此不能据此认定线上已部署全部功能。

本次仅新增报告、清单及检查日志，没有修改业务功能、版本公告或部署生产。报告优先依据现行 React 路由、ASP.NET 接口注册与业务代码，根目录早期数据库设计文档仅作为历史背景，不能替代当前实现。

## 3. 全部业务功能目录

下列接口路径除公开身份接口外一般以 `/api` 为前缀。表中使用模块路径表示一组接口，并非完整 HTTP 契约；逐条源码声明见配套清单。

### 3.1 账户身份、访问与个人中心

| 功能 | 用户入口 | 前后端实现 |
|---|---|---|
| 登录与会话 | `/login` | 登录、当前用户、刷新、退出；JWT 搭配服务端会话有效性验证 |
| 注册与邀请码 | `/register`、后台邀请管理 | 注册选项、邀请码校验、邀请创建/撤销；是否开放由服务配置与校验决定 |
| 个人资料 | `/profile` | 资料读取/修改、密码修改、头像上传/读取/删除 |
| 会话治理 | `/admin` | 管理员撤销指定用户会话 |
| 页面访问保护 | 登录后的业务路由 | `Protected` 调用当前用户接口；未授权清理缓存并跳转登录 |

证据：`AuthService*.cs`、`FinanceEndpoints.cs`、`SupportEndpoints.cs`、`LoginPage.tsx`、`RegisterPage.tsx`、`ProfilePage.tsx`。

### 3.2 首页与财务回忆

- **首页概览 `/`**：财务摘要、收支与资产信息、交易日历及进入业务模块的入口；后端提供 `/dashboard`。
- **历史上的今天 `/memories/on-this-day`**：日期候选、历史交易回顾、书签与专题 AI 分析；涉及 `OnThisDayService`、`FinancialMemoryService`、`MemoryAiEndpoint`。
- 回忆模块与 AI 记忆不同：前者组织历史财务事件，后者保存 AI 上下文或偏好。

### 3.3 交易中心与待整理工作台

入口：`/transactions`、`/transactions/review`、`/transactions/:id`。

- 日常支出、收入、账户转账、退款、信用卡还款、资产损失的录入与修改。
- 交易详情、分类分录、多个支付来源、商户、标签、项目、商品名称、备注等业务信息；具体字段随交易类型变化。
- 查询、分页、筛选、保存视图、每日汇总与当前范围汇总。
- 删除、恢复、批量预览与执行、批次结果查询；审计历史与操作结果恢复查询。
- 待整理状态、人工复核、问题明细、账单匹配及匹配撤销。
- 八类异常提示：极端金额、重复交易嫌疑、分录不平衡、分类缺失、商户映射异常、退款关联异常、转账配对异常、日期异常。提示是复核线索，不直接证明交易错误。
- 附件上传、列表、下载及删除；交易范围 AI 分析。
- 退款来源查询与原交易关联，区别退款冲减费用与普通收入。

证据：`TransactionsPage.tsx`、`features/transactions/`、`FinanceEndpoints.cs`、`TransactionWorkspaceEndpoints.cs`、`TransactionWorkspace.cs`、`BatchService.cs`、`TransactionAiEndpoints.cs`。

### 3.4 导入、清洗与导出

入口：`/import`。

- 账单文件上传、导入任务与行数据查询、字段映射、标准 CSV 模板。
- 导入行编辑、重新检查、重复候选人工处理、导入过程中创建分类。
- 导入清洗规则、商户主数据及别名、商户合并预览/执行、标准化刷新；清洗记录导出与撤销、建议采纳/拒绝、AI 导入识别；执行历史、尝试记录与逐行结果。
- 提交前预览/检查与正式提交分离，保留失败和重试追溯信息。
- 交易导出任务与文件下载；自定义报表另有预览、执行和导出接口。
- 工资条使用独立导入流程，不能把通用账单导入与工资条导入视为同一入口。

证据：`ImportPage.tsx`、`features/imports/`、`OperationsEndpoints.cs`、`ImportCleaningEndpoints.cs`、`StandardImportFields.cs`。未验证任意银行、任意格式文件均能直接识别。

### 3.6 账户管理、信用卡与对账

入口：`/accounts`、`/accounts/:id`、`/reconciliation`。

- 账户新增/编辑、分组、排序、归档/恢复、账户导入。
- 卡片资料维护，包含银行分行及卡号相关数据字段；展示与保存规则应按对应页面和权限处理。
- 账户详情、收支统计、活动摘要、健康检查、关联资源与审计历史。
- 单账户删除影响预览、账户删除及批量清理接口。
- 信用卡账期查询与还款记账。
- 对账预览、保存对账与账户历史对账记录。

证据：`AccountManagementEndpoints.cs`、`AccountManagementService.cs`、`AccountStatisticsService.cs`、`OperationsEndpoints.cs`、`features/accounts/`。信用卡统计不等于已对接银行的法定账单核销系统。

### 3.8 实物资产中心

入口：`/physical-assets`。路由先进入 `ManagedAssetsPage`，再转入新版 `PhysicalAssetsPage`；不是只有旧版实物资产页面。

- 实物资产档案、分类、数量、原始成本、投入使用时间和扩展资料。
- 手工估值、直线折旧、余额递减、固定值、市值、数量乘单价六类计算方式。
- 在用、闲置、借出、维修、出租、转让、出售、报废、丢失、归档等生命周期状态。
- 事件历史、事件冲回、部分数量处置、成本关联及撤销。
- 账面价值、市值、可变现净值、重置成本等维度与专题分析。

证据：`PhysicalAssetEndpoints.cs`、`PhysicalAssetService.cs`、`PhysicalAssetMath.cs`、`PhysicalAssetReports.cs`。这些估值能力不能直接推导为完整的折旧费用自动入账或处置损益总账闭环。

### 3.10 报销、借出借入与还款计划

- **报销 `/reimbursements`**：业务对象、垫付与结算、业务状态、关联交易删除/恢复。
- **借出借入 `/loans`**：债权/债务业务、详情、分次结算、状态与历史关联。
- **借款还款计划 `/loan-schedules`**：本金、借款日、首期日、期数、年利率、逾期日利率；等额本息、等额本金、先息后本；逐期本金/利息/逾期利息和支付日期调整；预览、保存与详情。
- **债务压力分析**：债务计划与信用卡分期计划、偿债顺序预览、还款分配及撤销、提前结清预览、计划历史与偿债压力计算，配合报表分析入口。

证据：`BusinessPage.tsx`、`BusinessService.cs`、`LoanScheduleService.cs`、`DebtPlanningEndpoints.cs`。计划中的支付日期标记不能直接视为银行实际扣款已成功。

证据：`FinancialPlanningEndpoints.cs`、`PlanningMath.cs`、`SavingsGoalService.cs`、`BudgetAlertScheduler.cs` 及 `features/planning/`。

## 4. 后端一致性与安全机制

1. **认证与隔离**：主体业务接口挂在需要授权的 `/api` 路由组，用户身份由认证声明取得；协作模块另有空间成员/角色校验。
2. **会话失效**：JWT 验证之后查询会话是否撤销、是否过期，不仅依赖 token 签名。
3. **财务数据模型**：交易头、分录、账户、分类及专项业务实体协作；服务端负责金额、状态、关联对象与余额规则。
4. **写入保护**：多处写接口使用统一 `Write` 包装、`Idempotency-Key`、`If-Match`/版本检查及预览后执行；应逐接口核查，不能推断所有写操作完全相同。
5. **输入与错误处理**：请求形状过滤、统一错误码与追踪 ID、并发冲突 409、重复记录冲突处理。
6. **认证请求保护**：认证路径存在来源检查和反伪造处理；登录有单独逻辑，不能声称每个接口均采用同一 CSRF 策略。
7. **限流**：登录、注册、个人资料及 AI 配置限流策略。
8. **隐私与文件**：AI 隐私服务、密钥受保护存储、头像处理、附件归属校验；响应默认 `no-store`。
9. **运行维护**：健康检查、数据库初始化/迁移入口、隔离恢复验证数据库命名限制、发布与备份脚本。

以上是代码机制清单，不是渗透测试、全量并发测试或生产数据恢复演练的结论。

## 6. 检查发现与功能边界

| 优先级 | 发现 | 证据与影响 |
|---|---|---|
| 高 | 多支付来源消费编辑测试稳定失败 | `frontend/src/tests/MultiPayment.test.tsx:134`：点击保存后未观察到 `transactionApi.save` 调用；全量运行与单文件复跑均失败。应检查表单校验、测试数据与保存链路，本次尚未确定真实界面是否同样受影响 |
| 中 | 统计说明与新版实物资产实现存在不一致 | `statisticsPolicyCatalog.ts` 的 `depreciation` 文案仍称当前仅手工估值；`PhysicalAssetMath.cs` 已有直线和余额递减计算。应更新说明，并区分估值折旧与总账费用入账 |
| 中 | 尚未提供完整历史折算/外汇成本统计 | 统计目录将全账本历史交易自动折算、部分汇兑口径明确列为不可用；不能按最新汇率替代全部历史事实 |
