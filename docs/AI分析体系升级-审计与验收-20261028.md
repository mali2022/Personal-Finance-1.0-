# AI 分析体系升级：审计与验收

## 审计基线

审计日期：2026-10-28，Asia/Shanghai。工作区包含尚未发布的人生模拟改动，本报告不将其视为线上能力。

- 普通聊天、首页洞察和财务报告均调用 `DeepSeekChatService`，但它只注册 `AiFinancialTools`；Agent 另有 `AiAgentTools`，交易筛选、详情、交叉分组、目录和情景工具未共享。
- 原财务工具共 22 项（包括工作区的人生模拟），按 summary/details/payroll/family 分项授权。账户限定仅支持五个汇总工具，其他工具保守拒绝，不能通过取消账户限制解决。
- 原交易工具固定第一页，只有起止日、币种和账户参数，没有分类筛选、分页、排序。Agent 搜索具备分类、标签、商户和分页，未接入聊天。
- 聊天上限已是 64 轮、128 个工具，不是固定一次调用；缺少按任务分级预算、重复查询检测和请求内缓存。默认总超时 120 秒。普通聊天只保留历史问题，未保留先前交易调查锚点。
- Agent 自动模式可使用宽泛的长期写授权，不满足本次“每项具体变更确认”的要求。已有预览、计划哈希、版本校验、幂等、事务及高风险单独授权应保留。
- 各财务工具调用 FinanceService 原领域服务；报表中心已有退款、手续费、原币及未结束期间口径。不能从单页流水重算全量统计。
- `AiAnswerValidator` 只校验数值是否出现在来源中，不能证明因果；聊天最终忽略其修正文案，只返回 verified 布尔值。不能把 verified 当作整段解释的语义证明。
- 首页直接输出字符串，报告使用 pre，Copilot 使用保留空白的正文；无统一 Markdown 或结构化报告协议。依据组件在正文显示大量原始 JSON。
- 已有身份认证、UserId 过滤、账户范围、授权版本、取消、配额预留、并发门禁、工具审计；Agent 自有只读工具缺少与普通工具一致的调用审计。
- UTF-8 容量检查按默认 JSON Unicode 转义放大中文；此前已修正出站序列化。仍须保持容量与 Token 预算分离，不应无限增大预算。

## 实施与验证

本次已实际修改后端授权、工具执行、调查编排、财务查询、模型协议、历史保存、前端渲染及自动化测试。以下是已落地范围与实际证据，不代表生产部署已经完成。

### 1. 分级授权

- 新增 `AiPrivacySetting.PersonalReadAccess`。新设置默认采用本人只读分析；服务端 AI 总开关和用户 Enabled 仍是必要条件，未开启 AI 不会传输数据。
- 已存在的分项拒绝通过迁移保留为自定义模式，避免静默扩大历史授权；用户可在 AI 设置中一次切换到本人自动只读，或继续单独限制汇总、明细和薪酬。
- 家庭数据、OCR/ASR 文字、历史保存保持独立控制；商户和备注等描述文字遵从高级设置。卡号、合同号、持有人、敏感标识和附件继续剔除。
- 高级设置的账户范围同时约束 Copilot 与 Agent；请求不能扩展到配置以外账户，已保存宽范围会话在范围收窄后不能继续复用。每次读取和模型调用前检查收窄或撤销。
- L1 查询自动执行；L2 建议可自动生成；L3 财务变更必须批准具体预览哈希；L4 删除及其他高风险操作继续使用独立计划授权。旧长期授权不能代替当前变更计划确认，包括 Auto 模式和定时工作流。
- Copilot 同样继承个人日/月费用限制，并与服务端额度取更严格值；缺少可核算费率时维持原有安全拒绝。

### 2. 工具与自主调查

实际注册清单为 22 个财务工具、31 个 Agent 工具；聊天只共享其中的只读工具，不注册财务写入能力。`SubmitAnalysis` 是结构化结果提交协议，不执行领域写入。

| 范围 | 已接入能力与限制 |
|---|---|
| 收支、分类、账户、预算、报表 | 复用 Report、Budget、FinancialReportCenter、PeriodReview、统计规则等原服务 |
| 交易、转账、退款 | SearchTransactions 支持类型、金额区间、异常规则、分类、账户、标签、商户、排序和分页；GetTransactionDetail 提供授权范围内的关联交易，最多20项并标明可能截断 |
| 变化与驱动 | AnalyzeDimensions 复用自定义分组；CompareFinancialPeriods 服务端计算自然月与上月可比窗口、差额与变化率 |
| 剔除大额支出 | AnalyzeExpenseExclusion 使用 decimal 和原统计规则，连同期间内关联退款一起剔除，返回贡献金额、占比和剔除后结果；不改变账本，不将大额自动判为一次性 |
| 资产、负债、投资、目标 | 复用现有净资产、借贷、投资表现、目标工具；实体枚举增加投资资产、投资交易、实物资产和定存，沿用原服务覆盖范围 |
| 周期账单、计划 | 共享 ListFinancialEntities 的周期账单、偿债计划、自动化规则、现金流情景等分页读取；ForecastScenario 为明确假设下的确定性计算 |
| 智能对账 | GetReconciliationEvidence 只读返回指定账户当前对账状态、差异和匹配引用；不能确认、撤销或修改匹配 |

月度综合分析会自动查询财务报告、全部已选账户的汇总、可比期间及大额支出，并继续取得主要交易详情。交易明细预读最多选择三个账户、每个账户十条；这只是调查起点，全部账户的总指标不受该样本限制，后续模型仍可在预算内查询其他已选账户和分页。

模型可根据中间结果继续选择工具；相互独立的只读调用使用独立依赖作用域/DbContext，并以信号量限制并发，避免并行使用同一个 EF 上下文。模型不能通过客户端参数传入 UserId、SQL 或写操作绕过授权。

按任务区分快速查询预算（默认8）与深入分析预算（默认32），同时受总轮数、总工具数、执行时间、上下文容量、输出容量、配额预留与并发限制。相同规范化查询在单次调查内复用，重复超过阈值返回循环提示，不跨用户或请求缓存财务结果。

工具失败保留失败状态和已成功证据；超时、上下文或资源限制可返回明确标记的局部报告并保留可继续的会话。用户主动取消不保存未完成回答。授权变化和越界拒绝不会作为普通失败被忽略后继续传输。

### 3. 财务口径与历史问题修复

- 当前期间使用统一查询截止时点，未来日期的已录入交易不能混入当前已发生事实。
- 未结束自然月按相同已过时长比较，包含时分秒并受上月月末截断；已结束月份比较完整自然月。零或负基期不产生误导性的变化率。
- 财务报告和比较工具共享月度窗口计算；预算、交易搜索、交叉分组支持同一截止时点，原有页面默认行为保持兼容。
- 收支结余与流动现金流明确区分；内部转账、借贷本金、退款、手续费及统计开关沿用原领域服务。不将不同币种相加，不从单页明细重算全量。
- 同范围与期间出现冲突快照时，自动补查统计规则并刷新一次汇总；完整冲突依据保留，不强行合并。
- 修复默认 JSON Unicode 转义放大中文容量的问题，统一按实际 UTF-8 出站表示检查并压缩完整历史工具轮次。
- 修复旧模型名兼容、用量记录与实际提供方模型标识不一致的问题；保留推理工具能力校验。
- 修复流式调用只接受最终文本的问题：可重组分片工具参数、处理空 choices 的 usage 帧、识别截断；普通流式聊天不再为同一最终回答额外生成第二遍。
- 回归发现并修复 UUID 被误识别为年月，或被银行卡脱敏规则改写导致随机查不到交易的问题。权威大额金额不再被脱敏器当作卡号修改；真实卡号、凭据和个人敏感文字仍脱敏。
- 未提供的金额/异常筛选不会以空参数传给领域查询，避免被误当作需要解析的金额。

### 4. 结构化协议与页面

`AiAnalysisReport` 版本为1，包含标题、报告类型、期间、生成时间、数据截止、币种、摘要、指标、分项发现、异常追踪、分类、趋势、建议、置信覆盖、限制和深入分析操作。模型通过 `SubmitAnalysis` 返回结构化发现和建议；关键金额、分类及图表数据由服务器从领域依据投影，而不是信任模型提交的图表数值。

每条发现携带依据ID；服务端清除不存在的引用，并区分服务端事实、数值有依据的解释、待核验解释和建议。建议支持优先处理、值得关注、长期优化。自由解释中的因果关系不能仅凭数值匹配证明，界面明确保留这一差别。

- 首页财务洞察、Copilot、月/年报告与 Agent 完成结果共用 `AiAnalysisView`。
- 共用金额卡、分项发现、趋势线、分类条形图、建议、按项展开依据和继续追问；金额复用 Money 的精确格式化。
- 首页进入 Copilot 时传递会话ID；报告追问继续同一会话。历史仅携带问题和调查定位，不将上次金额当作本次事实。
- 结构化报告保存到 `AiMessage.AnalysisJson`；历史纯文本记录使用保存的当时依据生成兼容展示，不重新查询并覆盖旧快照。
- Agent 保存报告、交易助手、实物资产、历史上的今天、共享账本及时间资产解释共用 Markdown 组件。专用模块仍保留原有领域证据和独立授权协议，不将共享账本冒充个人账本。
- 使用 react-markdown、GFM、受限数学渲染；支持标题、强调、列表、表格、引用、代码和链接。禁用原始 HTML、危险协议和第三方图片自动请求，数学渲染不启用信任模式。
- 普通业务页面按需加载 Markdown/数学依赖；依据默认折叠，支持直接定位交易或带筛选的列表。布局支持深浅色、手机、金额右对齐和可访问图表数据入口。

### 7. 尚存边界与后续建议

1. 自由文本的因果解释与一次性判断不是确定性证明。数值匹配只支持数值核对，不能证明商户、类别或原因归属正确；重要原因必须结合具体依据阅读，模型无权自动改账。
2. 任意主题的深入调查仍依赖模型工具选择；月度综合问题有确定性前置调查，但不保证每种措辞、每家上游模型都采取完全相同工具链。
3. 指定多个账户时，交叉分组及剔除支出部分服务仍要求逐账户查询，以避免扩大范围或泄漏跨账户拆分；不通过放开全账本来规避限制。后续可在原领域服务补充严密的多账户过滤能力。
4. 分组服务保留原有明细计算上限，部分实体服务在内部仍加载用户范围的快照。大规模资产/复杂交叉聚合可继续优化 SQL 与投影；工具预算、分页、结果容量和数据库超时保持有效。
5. 长时间调查与变化中的账本不是跨全部查询的不可变数据库快照。已统一时间窗口，且会提示/复核冲突；需要严格的历史快照审计时可再扩展版本一致性能力。
6. 真实提供方验证覆盖连接、流式及结构化协议；没有将正式用户数据发送给测试模型，也不把合成浏览器路由当作真实上游推理质量评测。复杂长链与全部异常类别仍值得增加持续评测。
7. 数学及 Markdown 增加了按需资源，生产构建仍报告既有大分块；后续可继续拆分主包，不能通过关闭安全渲染降低体积。
