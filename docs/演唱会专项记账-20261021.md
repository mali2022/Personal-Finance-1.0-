# 演唱会专项记账

产品版本：6.3.0；发布号：2026.10.21.4。

## 启用方式

设置 → 可选模块 → 演唱会专项记账。按当前登录用户保存在服务端，默认关闭；启用后出现在专项财务。关闭后隐藏入口并拒绝模块接口访问，已有档案、附件和真实账本不删除。再次开启可继续使用。

## 档案和门票

每场演出独立保存艺人、巡演名称及可扩展的巡演分组ID、标题、开始日期时间、城市、场馆、内部编号、主办方、平台、预算、预计与实际人数、备注、附件及场次状态。

场次支持计划中、抢票中、已购票、待演出、已参加、已取消、已延期。订单独立支持购票计划、抢票、待支付、已支付、已出票、已验票/使用、取消、延期，另设退款状态。服务器校验允许的状态转换、用户归属和数据版本，保留修改前快照和状态审计。

同一用户内，平台名称去除首尾空格并忽略大小写；订单号仅去除首尾空格，保留大小写与平台自身格式。同平台重复订单号拒绝，不同平台允许相同号码，尚无订单号的计划可留空。

单张票面价格与实付总额独立存储。实付总额包含手续费，不能把手续费再次加到付款金额；已关联付款后自动生成门票净额与手续费两笔专项归属，合计严格等于实付额，优惠不生成收入。实际支付可从页面调用原记账流程，再关联对应消费。订单状态本身不创建、撤销或退款任何账本交易。

同行购票若已通过原代付服务记账，可在订单的组合付款中分别选择本人消费与代垫本金流水，填写各来源归属金额和其中手续费；两项合计分别核对订单实付与手续费。组合与单笔关联互斥，不再新建重复付款。代垫本金只能取其完整原始应收，自动建立同行应收关联；本人手续费归属原本人消费。已关联付款的来源保留，退款从原服务处理。

## 费用、预算和退款

门票、交通、住宿、餐饮、周边、应援、寄存、保险、手续费和其他费用均以明确金额关联现有交易；可选择原交易的消费拆分分录。服务端在用户写锁事务内校验同一交易跨场次的累计归属上限，以及指定分录的归属上限。金额计算使用服务端 decimal，前端金额差使用现有整数分工具。

现有项目预算以整笔 ProjectId 交易统计，不能表达本模块所需的部分金额归属与分类预算，因此本模块使用经过上限验证的专项分配。报告只读该分配，不叠加原项目汇总，不提供手工预算执行金额。

总预算与六类预算独立于正式账本，分类合计不得超过总预算。未发生的费用只列计划；标记为已发生时必须关联已核算费用，且不再次累加实际金额。预算剩余=总预算−已发生净费用；另列扣除未发生计划后的可用额。

退款分申请、批准、实际部分/全额到账、拒绝。只有已确认、属于原交易、同币种的实际退款分配冲减成本，且同时受原费用与退款交易金额上限约束。不可退费用继续作为成本。取消与延期不等于退款到账。原交易或退款撤销后，相关归属从报告中排除并显示核对提示；未明确分配的退款显示提醒，不擅自按整笔冲减本场。

## 同行与代付

同行只记录姓名或昵称及付款、持票、承担角色，不要求注册，不收集联系方式或证件。比例与分摊金额须核对，未关联的分摊仅为计划，不推断到账。

选择现有代买代付原始垫付流水的完整应收本金时，自动建立当前用户的同行应收关联；本人承担部分须另关联该代付生成的本人消费流水。已结算、待结算、商家退票、赠与及核销均从原代付服务读取。费用赠与或核销不可重复作为普通费用归属；实际收回应收不算收入。不同用户的档案及资金始终隔离。

## 报告与附件

单场显示原始费用、确认退款、全场净费用、本人净成本、分类费用、预算执行、计划、超支、占比和待结算垫付。年度按演出日期归属、按所选原币分别统计场次、已参加次数、本人总成本、平均成本、最高场次、艺人、城市、月度趋势与全场费用类别占比。不直接相加不同币种；当前没有自动跨币种合并视图。

附件可归属场次或订单，支持经扩展名和文件头校验的 JPG/PNG/PDF，单个最大10MB，每场最多100个；上传与读取均校验用户、场次、开关状态和必要的数据版本。

- 状态转换与门票实付/手续费计算测试。

- Chromium 360px 和1440px：设置开启、创建场次、创建订单；截图检查输入区和移动端滚动。
